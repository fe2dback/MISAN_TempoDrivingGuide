================================================================
 MISAN-TempoDrivingGuide 프로젝트 개요
 AI 기반 고속도로 유령정체 완화 및 템포 드라이빙 가이드
================================================================

[한줄 소개]
고속도로·도시고속도로 운전자에게 AI가 계산한 실시간 최적 속도와
차선 유지 가이드를 제공하여, 사고 없이 생기는 '유령정체'를 줄이는 서비스


----------------------------------------------------------------
1. 주제
----------------------------------------------------------------
- 유령정체(Phantom Jam) 완화를 위한 '템포 드라이빙' 가이드 서비스
- 템포 드라이빙: 앞차에 바짝 붙어 급가속·급감속을 반복하지 않고,
  일정한 속도와 간격을 유지하며 달리는 운전 방식
- 시범 구간: 서울 강변북로 (구리 토평 ~ 가양대교 북단)


----------------------------------------------------------------
2. 문제점
----------------------------------------------------------------
(1) 원인 없는 정체
    - 사고나 공사가 없는데도 도로가 막히는 현상이 자주 생긴다.
    - 선두 차량 한 대가 살짝 브레이크를 밟으면, 뒤차들은 반응이
      늦어서 점점 더 세게 감속하게 된다. 이 감속이 뒤로 갈수록
      커지면서 결국 차가 멈추는 '정체 파동'이 된다.
    - 이 파동은 시속 약 15~20km로 차량 흐름과 반대 방향(뒤쪽)으로
      퍼지기 때문에, 원인이 사라진 뒤에도 정체가 한동안 남는다.

(2) 운전자가 겪는 피해
    - 통행시간 지연
    - 잦은 가속·감속으로 인한 연비 저하와 배출가스 증가
    - 급감속 때문에 생기는 추돌사고 위험

(3) 기존 정보 서비스의 한계
    - 내비게이션은 "이미 막힌 곳"을 알려줄 뿐이고,
      정체가 생기기 전에 운전 방식을 바꾸도록 안내하지 않는다.


----------------------------------------------------------------
3. 해결 목표
----------------------------------------------------------------
(1) 핵심 아이디어
    - 도로 상황과 정체 파동을 AI로 실시간 분석한다.
    - 정체가 생길 지점의 뒤쪽 1~2km에 있는 차량들에게
      "지금은 OO km/h로 차선을 유지하세요" 같은 권장 속도를 안내한다.
    - 뒤차들이 미리 조금씩 속도를 맞추면 급정거 없이 파동이 흡수되고
      사라진다. (멈췄다 출발하는 것보다 천천히 계속 달리는 쪽이
      전체 흐름에 유리하다)

(2) 서비스 동작 순서
    ① 감지  : 속도·교통량 데이터에서 정체 파동의 시작을 찾는다
    ② 예측  : 파동이 언제, 어디까지 퍼질지 계산한다
    ③ 계산  : 뒤따르는 차량의 권장 속도와 차선 유지 여부를 정한다
    ④ 안내  : 앱이나 내비 화면으로 운전자에게 알린다
    ⑤ 검증  : 적용 전후의 통행시간, 속도 변화, 급감속 횟수를 비교한다

(3) 기대 효과
    - 통행시간 단축, 도로 전체의 흐름 안정
    - 급감속 감소로 추돌사고 예방
    - 연비 향상과 배출가스 감소


----------------------------------------------------------------
4. 필요 자료
----------------------------------------------------------------
[A] 교통 흐름 자료 (정체 감지·예측의 핵심)
    - 교통소통정보 : 도로 구간(링크)별 평균속도·통행시간, 5분 단위
    - VDS(차량검지기) : 지점별·차로별 속도·교통량·점유율,
                        약 30초~1분 단위
                        → 짧은 주기의 정체 파동을 잡는 데 꼭 필요
    - VSL(가변 제한속도) : 구간별 현재 제한속도
                           → 권장 속도의 상한 기준

[B] 정체 원인 구분 자료
    - 돌발상황정보 : 사고·공사·통제 정보
                     → 사고가 원인인 정체를 빼고 '유령정체'만 골라냄
    - 주의운전구간정보 : 사고 위험 구간, 주의 구간

[C] 도로 구조 자료
    - 표준노드링크 : 도로 구간의 순서·방향·길이·차로 수
    - 진출입 램프·합류 지점, 차로 수가 줄어드는 곳, 터널·교량
      → 유령정체가 주로 시작되는 지점

[D] 외부 요인 자료
    - 기상(비·눈·안개), 요일·공휴일, 행사 정보

[E] 모델 개발·검증용 자료
    - 차량 주행 궤적 : 공개 데이터셋(NGSIM, highD 등),
                       국내 운행기록 자료 → 정체 파동 시뮬레이션
    - 교통사고 통계(TAAS) : 안전 효과의 근거


----------------------------------------------------------------
5. 현재 진행 상황 (2026-10-17 기준)
----------------------------------------------------------------
- 국가교통정보센터(ITS) OpenAPI 승인 완료
  : 교통소통정보, 돌발상황정보, VDS, 주의운전구간정보, VSL
- Python 수집 프로그램(collect.py) 작성
  : 위 5개 정보를 일정 간격(기본 60초)으로 자동 수집하고,
    종료하면 실행 시작 시각 기준으로 CSV를 정리해 저장
- 강변북로 링크 358개의 실시간 속도 수집 확인
  (예: 03:15 기준 구간 평균속도 56.9 km/h)

[다음 단계]
- VDS·주의운전구간·VSL 응답 구조 확인 및 수집기 보완
- 표준노드링크로 강변북로 구간을 방향·순서대로 정렬
- 시간-위치별 속도 지도(히트맵)를 그려 유령정체 파동 확인
- 정체 파동 예측 모델과 권장 속도 계산 방법 개발


----------------------------------------------------------------
6. 팀 역할 분담 (팀장 + 3명)
----------------------------------------------------------------
[팀장] 총괄
    - 일정·문서 관리, API 키 관리, 결과물 통합, 전체 총괄

[① 자료 수집·발표 자료] 데이터 수집·가공, 정보 정리, PPT 제작 (ppt, excel)
    - 수집 프로그램(collect.py) 운영, 수집 데이터 정리 (CSV, 엑셀)
    - 표준노드링크로 구간 방향·순서 정렬
    - 정체 패턴 정리 (언제, 어디서, 얼마나 자주 생기는가)
    - 분석 그래프: 시간-위치별 속도 히트맵, 정체 발생 통계
    - 발표용 PPT 제작 (문제 정의, 데이터 근거, 결과 정리)

[② Unity 시뮬레이션] 수집 자료 기반 시각화 테스트, 변수 테스트 (Unity)
    - 강변북로 구간을 Unity에 도로로 구현
    - 수집한 속도·교통량 자료로 차량 흐름 재현 (차량 추종 모델, 예: IDM)
    - 정체 파동 재현, 템포 드라이빙 가이드 적용 전후 비교
    - 변수 테스트: 가이드 준수율, 안내 거리(1km / 2km), 권장 속도 폭 등
    - 실데이터가 쌓이기 전에는 가상 도로·공개 궤적 데이터(NGSIM 등)로 먼저 개발

[③ 서비스 예시] 앱 또는 웹으로 서비스 예시 제작 (Web, App)
    - 운전자 안내 화면 (권장 속도, 차선 유지 안내)
    - 수집 데이터·시뮬레이션 결과를 보여주는 화면 (지도, 구간별 상태)
    - 화면 시안, 시연 구성안

[역할 간 약속]
    - ① → ② : 넘겨줄 CSV 형식(칸 이름, 단위)을 미리 정한다
                (수집기의 세션 CSV 기준, Unity에서 읽기 쉬운 형식으로)
    - ② → ③ : 시뮬레이션 결과 형식(시각 x 위치 x 권장 속도)을 미리 정해서,
                ③이 가짜 데이터로 화면을 먼저 만들 수 있게 한다
    - ②·③ → ①   : 각자 결과 화면(캡처, 영상)을 ①에게 넘겨 PPT에 반영한다
    - 성공 기준 : 무엇이 얼마나 줄면 성공인지 ②와 ③이 함께 정한다
                  (예: 통행시간, 속도 편차, 급감속 횟수 OO% 감소)
    - 권장 속도 계산(AI) 담당 : ②가 Unity 시뮬레이션 안에서 구현하는 것을 기본으로 하고,
                  필요하면 ③의 서비스 화면과 같은 계산 방식을 쓰도록 맞춘다
